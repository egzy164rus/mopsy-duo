# Публикация игры в Telegram — пошагово, простыми словами

Эта инструкция рассчитана на человека, который **никогда ничего не выкладывал в интернет**.
Никаких знаний программирования не нужно — только аккуратно нажимать кнопки.
Всё, что нужно вписать вручную, выделено **жирным**.

⏱ Полный путь «с нуля до игры в Telegram» — **20–30 минут**.
💸 Сначала можно сделать бесплатно (для проверки), для «по-настоящему» — примерно 7 $/мес.

---

## Часть 0. Что вообще происходит (прочитайте один раз)

Ваша игра — это **папка с файлами** (в ней лежит `package.json`, папки `server`, `public`).

Чтобы Telegram мог её показать, папка должна лежать на компьютере, который:

1. работает круглосуточно (ваш ноутбук для этого не подходит),
2. имеет адрес в интернете вида `https://mopsy-duo.onrender.com`,
3. умеет запускать маленькую программу (`node server/index.js`).

Такой компьютер называется **хостинг**. Мы возьмём Render.com — он бесплатный на старте
и не требует командной строки.

Схема целиком:

```
ваша папка  →  GitHub (склад файлов)  →  Render (компьютер 24/7, даёт https-адрес)
                                              ↓
                             Telegram-бот открывает этот адрес в своём окне
```

---

## Часть 1. Словарик (5 терминов, которые будут ниже)

| Слово | Что это на самом деле |
| --- | --- |
| **Хостинг** | Компьютер в интернете, который работает всегда. Мы используем Render. |
| **Репозиторий / GitHub** | «Склад файлов» в интернете. Хостинг берёт файлы со склада. |
| **HTTPS** | Адрес с замочком 🔒. Telegram открывает игры только по таким адресам. Render выдаёт его сам. |
| **Токен бота** | Длинный пароль вида `7123456789:AAH...`. Он даёт власть над ботом — никому не показывайте. |
| **Mini App** | Игра, которая открывается внутри Telegram (как окно), а не в браузере. |

## Часть 2. Быстрый запуск (бесплатно, ~20 минут)

### Шаг 1. Закинуть папку игры на GitHub

GitHub — это бесплатный «склад файлов». Регистрация занимает 2 минуты.

1. Откройте **https://github.com** → **Sign up** → введите почту, пароль, придумайте логин.
   Подтвердите почту (письмо придёт на ящик).
2. Войдите → нажмите зелёную кнопку **New** (или плюсик `+` справа сверху → **New repository**).
3. Заполните:
   * **Repository name:** `mopsy-duo`
   * выберите **Public** (так проще, и Render бесплатно подключается к публичным складам)
   * галочку «Add a README file» можно оставить
4. Нажмите **Create repository**.
5. На странице склада нажмите **Add file ▾** → **Upload files**.
6. Откройте папку `mopsy` на компьютере и **перетащите мышкой в окно браузера всё её содержимое**:
   `package.json`, `render.yaml`, папки `server`, `public`, `docs`, `scripts`, `sql`.
   > ⚠️ Важно: перетаскивайте **содержимое** папки `mopsy`, а не саму папку.
   > Проверка: после загрузки на складе должен быть виден файл `package.json` в самом верху списка,
   > а не папка `mopsy/package.json`.
7. Внизу страницы нажмите зелёную **Commit changes** и подождите 10–20 секунд.

✅ **Что должно получиться:** на странице репозитория видно файлы `package.json`, `render.yaml` и папки `public`, `server`.

---

### Шаг 2. Создать «компьютер 24/7» на Render

1. Откройте **https://render.com** → **Get Started** → **GitHub** (вход через тот же аккаунт GitHub).
   Разрешите Render доступ к вашим складам (кнопка **Authorize**).
2. В панели Render нажмите **New +** (справа сверху) → **Web Service**.
3. Выберите ваш склад **mopsy-duo** → **Connect**.
4. Заполните поля ровно так:

   | Поле | Что вписать |
   | --- | --- |
   | **Name** | `mopsy-duo` |
   | **Language / Runtime** | `Node` |
   | **Branch** | `main` |
   | **Build Command** | `npm install` |
   | **Start Command** | `npm start` |
   | **Instance Type** | `Free` (для первой проверки) |

5. Прокрутите до **Environment Variables** → **Add Environment Variable**:
   * **Key:** `DEMO_MODE` → **Value:** `0`
     *(выключает демо-кнопки «Аня»/«Илья» с общеизвестным паролем;
     если хотите сначала сами пощупать демо — поставьте `1`, а потом поменяете)*

   > 💡 Что происходит с базой: при `DEMO_MODE=0` и пустой базе сервер стартует **без игроков** —
   > первый, кто откроет игру, создаёт своего мопса и приглашает второго. Если база уже была
   > и в ней остались демо-аккаунты, сервер напишет об этом в логах и подскажет команду
   > `npm run purge-demo` (удаляет Аню, Илью и их мопса, ваших игроков не трогает).
6. Нажмите **Create Web Service** (или **Deploy Web Service**).

Дальше Render сам всё скачает и запустит. Смотрите на чёрное окно с логами — ждите,
пока появится надпись вроде `Your service is live 🎉` (обычно 1–3 минуты).

✅ **Проверка:** сверху страницы есть адрес вида `https://mopsy-duo.onrender.com`.
Откройте его в браузере — должна появиться игра (экран входа с мопсом).
Ещё можно открыть `https://mopsy-duo.onrender.com/api/health` — если видите
`{"ok":true,...}`, значит сервер жив.

> 🐢 Если страница грузится ~30–60 секунд — это нормально: бесплатный инстанс «засыпает»
> после 15 минут простоя и просыпается при первом заходе.

---

### Шаг 3. Создать бота в Telegram

1. В Telegram найдите **@BotFather** (у него синяя галочка) → нажмите **Start**.
2. Отправьте ему сообщение: **`/newbot`**
3. Он спросит имя бота (то, что видят люди). Напишите: **`Мопсик вдвоём`**
4. Потом спросит юзернейм — он должен быть на латинице и заканчиваться на `bot`.
   Придумайте, например: **`mopsy_duo_bot`**
   *(если занято — добавьте цифры: `mopsy_duo_2026_bot`)*
5. BotFather пришлёт сообщение **Done!** и строку с токеном:

   ```
   Use this token to access the HTTP API:
   7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

   📌 **Скопируйте токен в заметки.** Это пароль бота. Никому его не отправляйте.

---

### Шаг 4. Отдать токен хостингу (чтобы вход был настоящий)

1. Вернитесь на Render → ваш сервис `mopsy-duo` → слева меню **Environment**.
2. **Add Environment Variable**:
   * **Key:** `TELEGRAM_BOT_TOKEN`
   * **Value:** вставьте токен из BotFather
3. Добавьте ещё две (это нужно, чтобы приглашения работали красивыми ссылками):
   * `TELEGRAM_BOT_USERNAME` = `mopsy_duo_bot` (ваш юзернейм бота **без @**)
   * `TELEGRAM_APP_SHORT_NAME` = `mopsy`
4. Нажмите **Save Changes** — Render перезапустит игру сам (1–2 минуты).

> Зачем это: с токеном сервер проверяет, что человек действительно пришёл из Telegram,
> а не подделал профиль.

---

### Шаг 5. Сделать кнопку, которая открывает игру

1. В Telegram снова напишите **@BotFather**:
2. Отправьте **`/mybots`** → выберите вашего бота (Мопсик вдвоём).
3. Нажмите **Bot Settings** → **Menu Button** → **Configure menu button**.
4. Он попросит адрес. Вставьте адрес Render целиком: **`https://mopsy-duo.onrender.com/`**
   *(обязательно с `https://` и со слэшем в конце)*
5. Он попросит название кнопки. Напишите: **`🐶 Играть`**

✅ Готово: в чате с ботом внизу появилась кнопка «Играть».

---

### Шаг 6. Проверка на телефоне

1. Откройте Telegram на телефоне → найдите своего бота → нажмите **🐶 Играть**.
2. Должна открыться комната с мопсом (или экран входа, если аккаунт новый).

**Что должно работать:**

| Что проверить | Как выглядит успех |
| --- | --- |
| Вход без пароля | вы сразу в игре, в профиле видно ваше имя из Telegram |
| Мопс живой | он дышит, моргает, реагирует на нажатия |
| Действия | нажали «Покормить» → тост «Бублик с удовольствием всё съел», полоска сытости выросла |
| Игры | «Игры» → любая игра → после окончания начисляются монеты |
| Гардероб | можно примерить шапку и купить её за монеты |

---

### Шаг 7. Пригласить второго игрока

1. В игре откройте раздел **Профиль** (или карточку «Пригласите второго хозяина» на главной).
2. Нажмите **Отправить ссылку** → выберите друга в Telegram.
3. Друг открывает ссылку вида
   `https://t.me/mopsy_duo_bot/mopsy?startapp=invite_ABC123` → попадает в игру →
   у него уже подставлен код приглашения → он нажимает «Присоединиться к мопсу».
4. Теперь вы оба видите одного мопса: покормите его — у друга это появится сразу же.

## Часть 3. Сделать «по-настоящему» (чтобы питомцы не пропадали)

На бесплатном тарифе Render **данные стираются** после перезапуска: сервис «засыпает»
и теряет файл базы. Для теста это неважно, для настоящих игроков — критично.

Выберите один вариант:

### Вариант А. Платный тариф Render + диск (~7,25 $/мес) — проще всего

1. Render → ваш сервис → **Settings** → **Instance Type** → выберите платный (Starter / 512 MB).
   Это отключает «засыпание».
2. Слева **Disks** → **Add Disk**:
   * **Name:** `mopsy-data`
   * **Mount Path:** `/opt/render/project/src/data`  ← ровно так, это папка с базой
   * **Size:** `1 GB` (этого хватит на годы)
3. **Save** → Render пересоберёт сервис. Теперь питомцы сохраняются навсегда.

> В проекте уже есть файл `render.yaml` с этими настройками. Если хотите, чтобы всё
> создалось автоматически: Render → **New +** → **Blueprint** → выбрать склад →
> Render прочитает файл и предложит создать сервис (нужно будет только вписать токен).

### Вариант Б. Свой сервер (VPS, 4–6 $/мес, нужны команды)

Если хочется полного контроля: скопируйте команды из файла **`docs/DEPLOY.md`**,
раздел «Вариант А. VPS + nginx + Let's Encrypt». Там всё готово — вставлять по одному блоку.

### Вариант В. Свой красивый адрес (необязательно)

Вместо `mopsy-duo.onrender.com` можно использовать `igra-mopsik.ru`:

1. Купите домен (например на reg.ru или namecheap) — примерно 200–1000 ₽/год.
2. Render → ваш сервис → **Settings** → **Custom Domain** → добавьте домен.
3. Render покажет, какие две записи прописать у регистратора домена (CNAME / A).
   Скопируйте их в панель домена — через 10–60 минут заработает.
4. Не забудьте поменять адрес в BotFather (Шаг 5) на новый.

## Часть 4. Если что-то не работает

| Симптом | Что делать (по порядку) |
| --- | --- |
| Нажал «Играть» — написано «Bot domain invalid» или пусто | Адрес в BotFather не совпадает. Повторите Шаг 5, вставьте адрес целиком с `https://` и `/` на конце |
| Игра открылась, но показывает экран входа с паролем (а не Telegram-профиль) | Не задан `TELEGRAM_BOT_TOKEN`. Render → Environment → добавьте токен → Save |
| «Подпись Telegram не совпала» | Токен от другого бота или скопирован не полностью. Скопируйте заново из BotFather |
| Страница грузится минуту и потом работает | Это бесплатный тариф «просыпается». Норма. Лечится платным инстансом |
| После перезапуска пропали мопсы | Нет диска (Часть 3, Вариант А). Пока его нет, данные не сохраняются |
| Изменения в игре не видны | Render → **Manual Deploy** → **Deploy latest commit**. Или подождите 2 минуты |
| Друг открыл ссылку, но код приглашения пустой | Не задан `TELEGRAM_BOT_USERNAME`/`TELEGRAM_APP_SHORT_NAME` (Шаг 4). Пока их нет, ссылка — обычная, но работает в браузере |
| В логах Render красные строки | Откройте **Logs**, найдите первую красную строку. Чаще всего — опечатка в переменных |
| Совсем ничего не получается | Напишите мне в чат: пришлите, что видно в **Logs** и на экране — разберём |

## Часть 5. Сколько это стоит

| Вариант | Цена | Плюсы | Минусы |
| --- | --- | --- | --- |
| Render Free | 0 $ | мгновенно, без карты | засыпает, данные стираются — только для теста |
| Render + диск | ≈ 7,25 $/мес | просто, HTTPS сам, не засыпает | зависит от чужого сервиса |
| VPS + nginx | ≈ 4–6 $/мес | полный контроль, дешевле | нужны команды и настройка |
| Свой домен | 200–1000 ₽/год | красивый адрес | не обязательно |

Внутри игры нет покупок — платить игрокам ничего не нужно.

## Часть 6. Как обновлять игру после изменений

1. На GitHub откройте нужный файл → значок карандаша ✏️ → измените → **Commit changes**.
   *(или снова **Add file → Upload files** и перетащите изменённые файлы)*
2. Render сам увидит изменение и пересоберёт игру за 1–2 минуты.
3. Откройте игру в Telegram заново (иногда нужно закрыть и открыть бота).

**Резервная копия базы** (важно, если используете файловую базу):

* Render → ваш сервис → **Shell** (на платном тарифе) → `cp data/db.json /tmp/db-backup.json`
  и скачайте файл, **или** проще: перейти на PostgreSQL по инструкции `docs/BACKEND.md`.

- [ ] `TELEGRAM_BOT_TOKEN` добавлен в Environment (вход без пароля работает)
- [ ] `DEMO_MODE=0` (демо-кнопки скрыты)

- [ ] Если нужна сохранность — подключён диск (Часть 3)

## Подсказка: проверка настроек одной командой

Если вы умеете открывать терминал (или у вас есть доступ к Shell на хостинге),
в проекте есть самопроверка:

```bash
npm run check
```

Она по-русски скажет, что уже настроено, а что нужно поправить перед публикацией —
например, что забыт токен, включён демо-режим или в базе остались тестовые аккаунты.

| Команда | Что делает |
| --- | --- |
| `npm run check` | проверка настроек перед публикацией |
| `npm start` | запустить игру на своём компьютере (http://localhost:3000) |
| `npm run purge-demo` | удалить демо-аккаунты Аня/Илья перед публикацией |
| `npm run reset` | полностью стереть базу и залить демо-данные заново |
